# HandFuture 多國語言與地區導流設計

**日期：** 2026-07-29  
**狀態：** 已由使用者核准  
**範圍：** 繁中、簡中、英文、日文、韓文、西班牙文、巴西葡萄牙文、法文

## 目標

讓 HandFuture 的公開內容具有可分享、可索引的語言專屬網址，首次造訪時依使用者既有選擇、瀏覽器語言與地區提示選擇合適語言，同時保留手動覆寫能力，不破壞既有八條公開網址、AdSense、CMP、隱私揭露或真實 404。

## 核心決策

- 正式語言代碼為 `zh-TW`、`zh-CN`、`en`、`ja`、`ko`、`es`、`pt-BR`、`fr`。
- 正式內容網址採 `/{locale}{publicPath}`，例如 `/ja/about`。
- `/` 是 `x-default` 入口；舊的無語言前綴內容網址保留相容導流。
- 語言優先順序為：使用者明確選擇 > 瀏覽器語言 > IP 國家提示 > 英文。
- IP 判斷只作為沒有其他訊號時的輔助，不鎖定語言；使用者可隨時切換。
- Cloudflare 維持 DNS-only。若需要地區代碼，由同網域 Vercel Function 僅回傳 ISO 國家代碼。
- 不保存完整 IP，不把地區代碼送進分析事件。
- AI 翻譯必須保留品牌、來源網址、日期、技術名詞以及醫療／財務／未來預測等免責界線。

## 使用者流程

### 第一次造訪

1. 若網址已有支援的語言前綴，直接使用該語言。
2. 若 `language-store` 有使用者曾明確選擇的語言，使用該語言。
3. 否則比對 `navigator.languages`：繁體中文映射至 `zh-TW`、簡體中文映射至 `zh-CN`，其餘支援語言映射至對應的一般版本。
4. 瀏覽器沒有可用訊號時，才向 `/api/locale` 取得國家代碼並映射建議語言。
5. 仍無法比對時使用 `en`。

搜尋引擎與無 JavaScript 訪客不依 IP 得到不同的主要內容；所有語言版本都透過固定網址、站內連結與 sitemap 可被發現。

### 手動切換

- 語言選單顯示八種語言的自稱名稱。
- 切換時保留目前的內容路徑，例如 `/en/privacy` 切換日文後前往 `/ja/privacy`。
- 明確選擇寫入持久狀態，此後優先於瀏覽器與 IP。
- 無對應頁面時只顯示該語言的 404，不退回首頁。

## 路由與相容性

- `PUBLIC_PATHS` 繼續描述八條內容路徑，不混入語言前綴。
- 新增 locale route parser／builder，負責驗證語言、拆解內容路徑及建立同頁語言網址。
- React Router 接受 `/:locale/*`，並把解析後的內容路徑交給現有頁面元件。
- 舊的 `/how-it-works`、三條 `/guides/...`、`/about`、`/privacy`、`/terms` 導向繁中對應網址，避免既有連結失效。
- 不支援的語言前綴或不存在內容路徑回傳／呈現真實 404 語意，並設定 `noindex, follow`。

## 翻譯資料架構

- 將 UI 字串與語言資訊拆到 `src/i18n`，每個 locale 一個可獨立審查的模組。
- 指南、運作方式、隱私政策、使用條款與 SEO metadata 使用相同 `Locale` 型別。
- 完整性測試保證每種語言具有相同鍵集合，不允許把翻譯鍵直接顯示給使用者。
- 品牌名稱 `HandFuture`、網域 `handfortune.com`、`MediaPipe`、`Vercel`、`Cloudflare`、`Google AdSense`、電子郵件與來源網址不翻譯。
- 翻譯不得新增偵測能力、命理準確性、醫療效果、財務結果或預測承諾。

## SEO

- 每個語言頁面以自己的完整網址作 canonical。
- 每個頁面列出八個互相對應的 `hreflang`，另列 `x-default`。
- `html[lang]`、Open Graph locale、JSON-LD `inLanguage` 與網址語言一致。
- sitemap 列出 64 條正式語言內容網址；不把查詢參數或轉址網址列入。
- robots.txt 繼續指向唯一 sitemap。
- 舊網址的轉址與 canonical 不形成循環。

## 地區映射

地區映射只在沒有明確選擇且瀏覽器語言不匹配時使用：

- `TW`、`HK`、`MO` → `zh-TW`
- `CN`、`SG` → `zh-CN`
- `JP` → `ja`
- `KR` → `ko`
- `BR` → `pt-BR`
- 主要西語國家 → `es`
- 主要法語國家 → `fr`
- 其他 → `en`

多語國家仍以瀏覽器語言優先，避免只由國家推定個人語言。

## 隱私與廣告

- 隱私政策新增「語言與大致地區」說明：瀏覽器語言、本機語言偏好，以及 Vercel 由請求 IP 推導的國家代碼可能被用於語言建議。
- 不新增行銷追蹤器，不記錄完整 IP，不建立語言／地區使用者剖析。
- AdSense publisher ID、`ads.txt`、廣告載入標籤及 Google-certified CMP 設定保持不變。
- 多語頁面的隱私政策與條款保持同等可達性。

## 驗證與發布

- 單元測試：locale 正規化、瀏覽器語言、國家映射、路由拆解與建立、翻譯鍵完整性。
- 元件測試：語言切換保留頁面、metadata／canonical／hreflang、語言 404。
- 內容 audit：敏感宣稱、來源、日期、品牌與聯絡資料一致。
- 發布前檢查：64 條正式網址、舊網址導流、真實 404、sitemap、robots、ads.txt、CMP 強制測試網址。
- 先在 Vercel Preview 驗證；未經明確發布步驟不改正式站。

## 非目標

- 不依城市或精確座標客製內容。
- 不為每個英語、西語或法語國家建立獨立區域版本。
- 不啟用 Cloudflare Proxy 或 Workers。
- 不在這次變更中調整廣告版位、CMP 後台或 AdSense 審查狀態。
